1. Overview — What is the Login Page?

The Tanseeq Web App uses Microsoft Sign-In (also called Microsoft OAuth or SSO — Single Sign-On). This means there is no username/password form on the page. Instead, the user clicks one button — "Sign in with Microsoft" — and is redirected to Microsoft's own login page to enter their company email and password there. Microsoft then confirms to our app that the login was successful, and the user lands on the dashboard.

🔑 Why Microsoft Login? The company already uses Microsoft 365 (Outlook, Teams, etc.). By using Microsoft login, employees use the same password they use for email — no new passwords to remember, no passwords stored in our database, and IT manages access through Azure AD.

The flow is called OAuth 2.0 — an industry-standard protocol for secure sign-in without sharing passwords.

2. What the User Sees on Screen

When a user visits the app URL (e.g. https://yourapp.com), they see a single dark-themed login card:

Red error box (shown only on failure) Message like "Access is restricted to company accounts only" Laravel session flash message from the backend
⚠️ Note for non-technical readers: A "flash message" is a one-time message stored in the user's session. It appears once after a redirect and then disappears — like a pop-up that automatically closes after you read it.

The page file is: resources/views/welcome.blade.php

The relevant button line in the code:
<a href="{{ route('auth.microsoft') }}" class="microsoft-btn"> Sign in with Microsoft </a>

{{ route('auth.microsoft') }} is Blade syntax (Laravel's templating language) that automatically generates the correct URL: /auth/microsoft. This means if the URL ever changes, you only change it in one place (routes) and every page updates automatically.

3. Step-by-Step Login Flow (User → Dashboard)

The complete journey from clicking the button to arriving at the dashboard involves 8 steps:

1
User visits the app URL The user opens the browser and goes to the app (e.g. http://outlook-mailtest.test). Laravel routes this to the welcome view, which displays the login card.

Route: GET / → shows welcome.blade.php
2
User clicks "Sign in with Microsoft" The button is a link to /auth/microsoft. Clicking it sends a GET request to our server.

Route: GET /auth/microsoft → MicrosoftOAuthController@redirectToMicrosoft
Rate Limited: 15 clicks per minute per IP address
3
Server builds the Microsoft login URL and redirects The controller checks that Azure credentials are configured, then uses the Socialite library to build a special Microsoft login URL that includes our App ID and a security "state" token. The browser is redirected to Microsoft's login page.

Example Microsoft URL generated:
https://login.microsoftonline.com/{tenant-id}/oauth2/v2.0/authorize ?client_id=401538ec-9257-479c-99fb-009f10765b30 &redirect_uri=https://yourapp.com/auth/microsoft/callback &scope=openid profile email User.Read &state=abc123securetoken &response_type=code
4
User enters their Microsoft (company) credentials This happens entirely on Microsoft's servers — our app never sees the password. The user enters their company email and password on Microsoft's own page. If the company uses MFA (Multi-Factor Authentication), that happens here too.
5
Microsoft redirects back to our app with an authorization code After successful authentication, Microsoft sends the user's browser back to our configured callback URL with a short-lived code:

GET /auth/microsoft/callback?code=ABCDEF&state=abc123securetoken

Route: GET /auth/microsoft/callback → MicrosoftOAuthController@handleMicrosoftCallback Rate Limited: 15 per minute per IP
6
Our server exchanges the code for the user's profile The handleMicrosoftCallback method runs. Behind the scenes, Socialite makes a server-to-server call to Microsoft to exchange the code for an access token, then fetches the user's profile (name, email, Microsoft user ID). The browser code is never stored.

Three checks happen immediately:
  • ✅ Is the email not empty?
  • ✅ Is the email on the allowed domain (tanseeqinvestment.com)?
  • ✅ Does the Azure App ID and Secret match what we have configured?
If any check fails → redirect back to login page with an error message.
7
User is found or created in our database The app looks up the local users table by email address:

Scenario What happens
User exists No action needed. If their microsoft_id field is blank (legacy account), it gets filled in silently.
User does NOT exist A new row is created in users table with name, email, microsoft_id. A random 32-character password is generated (they will never use it — login is always through Microsoft).
8
Session is created and user lands on dashboard Three things happen in sequence:
  1. Session ID is regenerated — a new unique session ID is issued to prevent a security attack called "session fixation".
  2. Auth::login($user) — Laravel marks this browser session as authenticated for this user.
  3. Redirect to dashboard — the user is sent to /dashboard.

From this point, every page request checks the session to confirm the user is still logged in. The session is stored in Redis (Upstash cloud), encrypted with the app key.

5. Security Features Built Into Login

The login page has 7 security protections active:

# Security Feature What it prevents Where it is
1 Rate Limiting (15/min) Bots/attackers cannot click the login button hundreds of times per second. After 15 attempts per minute from the same IP address, they get a "429 Too Many Requests" error. routes/web.php — ->middleware('throttle:15,1')
2 Domain Restriction Only emails ending in @tanseeqinvestment.com can log in. Someone with a Gmail or competitor email who somehow has a Microsoft account cannot access the system. MicrosoftOAuthController@emailDomainAllowed
3 Session Regeneration Prevents "Session Fixation" — a trick where an attacker pre-plants a session ID in a link, then waits for a victim to log in with that link, and hijacks their session. By generating a brand new session ID immediately after login, the old planted ID becomes useless. $request->session()->regenerate() in controller
4 Encrypted Sessions Session data stored in Redis is encrypted using AES-256. Even if someone read the raw Redis data, they would see gibberish. SESSION_ENCRYPT=true in .env
5 No Error Leaking Error messages shown to the user are generic ("Authentication failed. Please try again"). The actual technical error (PHP exception, stack trace, D365 details) only goes to the server log — never visible to the user or in the HTML source. Error constants in MicrosoftOAuthController
6 HTTP Security Headers Every page response (including login) includes headers that instruct the browser on how to handle the page securely:
  • X-Frame-Options: SAMEORIGIN — prevents the page being embedded in an iframe on another website (clickjacking attack).
  • X-Content-Type-Options: nosniff — prevents browser from guessing file types (MIME sniffing attacks).
  • X-XSS-Protection: 1; mode=block — extra browser-level cross-site scripting protection.
  • Referrer-Policy — controls what URL information is shared when navigating away.
  • Strict-Transport-Security — forces HTTPS for 1 year (active in production).
 SecurityHeadersMiddleware.php
7 No Password in Our Database Microsoft handles password verification entirely. Our database only stores the name, email, and Microsoft user ID. Even if our database were somehow accessed, there are no passwords to steal. Architecture decision — OAuth 2.0 by design

6. Error Handling — What Goes Wrong and Why

There are 5 error scenarios the login handles gracefully:

Scenario What user sees What actually happened Logged?
Azure credentials not configured "Authentication is not available right now. Please contact the administrator." AZURE_CLIENT_ID or AZURE_CLIENT_SECRET is empty in .env Yes — Log::error with which config keys are missing
Microsoft returns no email "Authentication failed. Please try again or contact support." Microsoft didn't include the email in the profile response (rare edge case) Yes — Log::warning
Email outside allowed domain "Access is restricted to company accounts only." Email domain is not tanseeqinvestment.com Yes — domain logged (not full email)
General OAuth failure "Authentication failed. Please try again or contact support." Any PHP exception during callback (network issue, Microsoft error, invalid state token) Yes — full exception class and message logged
User cancelled on Microsoft page "Authentication failed. Please try again or contact support." Microsoft sends error=access_denied to the callback URL Yes — oauth_error and error_description logged
📋 Where to find login errors: All login errors are written to the Laravel log file at storage/logs/laravel.log. Search for "Microsoft OAuth" in that file to find any authentication issues.

7. Sessions — How the App Remembers You Are Logged In

After login, the app needs to remember who you are for every click and page load. This is done through a session.

How it works:

  1. When you log in, the server generates a unique random session ID (e.g. abc123xyz789...).
  2. This session ID is stored as a cookie in your browser (called laravel_session).
  3. The actual session data (your user ID, any temporary messages, etc.) is stored in Redis — a fast in-memory database hosted on Upstash (cloud).
  4. On every page request, your browser sends the cookie → the server looks up the session data in Redis → confirms you are logged in.
Session Setting Value Meaning
SESSION_DRIVER redis Sessions are stored in Redis (fast, survives server restarts)
SESSION_LIFETIME 120 minutes You are automatically logged out after 2 hours of inactivity
SESSION_ENCRYPT true Session data in Redis is encrypted — unreadable without the app key
Redis host Upstash cloud Sessions survive a server restart — no one gets logged out when the app restarts
⚠️ Session Security Note: The session cookie is marked HttpOnly (JavaScript on the page cannot read it) and SameSite=Lax (prevents it being sent from external websites). In production, it should also be marked Secure (HTTPS only).

8. Logout Flow

Logging out is handled by the logout method in MicrosoftOAuthController:

1
User clicks the logout button This sends a POST request to /logout (POST is used, not GET, to prevent logout being triggered by a link visited accidentally).
2
Auth::logout() Clears the authentication state from the current session — the user is no longer considered logged in.
3
$request->session()->invalidate() Deletes the entire session from Redis. The session ID cookie in the browser now points to nothing.
4
$request->session()->regenerateToken() Issues a new CSRF token so any form data from the old session cannot be replayed.
5
Redirect to / User sees the login page again, fully logged out.
📌 Note: This logout only ends the session with our app. The user is not logged out of Microsoft itself. If they click "Sign in with Microsoft" again immediately, Microsoft may sign them in automatically without asking for a password (because they are still signed into Microsoft in the browser). This is standard behavior for all Microsoft OAuth apps.

9. Core Concepts Explained Simply

Term Simple Explanation
OAuth 2.0 A standard protocol (set of rules) that lets you use "Sign in with Google/Microsoft/etc." on other websites. The website never gets your password — it just gets a confirmation from Google/Microsoft that you are who you say you are.
SSO (Single Sign-On) One login works for multiple systems. Since we use Microsoft SSO, your company Microsoft email/password unlocks both Outlook, Teams, AND this app. IT manages all access from one place.
Authorization Code A short-lived temporary code (valid for ~1 minute) that Microsoft gives our server after you log in. Our server uses it to fetch your profile. It's like a ticket at a counter — you get it, hand it in, and get your profile back.
Access Token A longer-lived credential that the server uses to talk to Microsoft's API and fetch your name, email, and user ID. Never shown to the user or the browser.
Socialite (library) A Laravel package that handles the complex OAuth steps automatically. Without it, we'd have to write hundreds of lines of code to build URLs, validate tokens, and fetch profiles. Socialite reduces this to 3 lines of code.
Session A way for the server to remember who you are between page clicks. Websites are stateless by default (each click is like meeting the server for the first time). A session gives you a "membership card" (the session cookie) that you show on every visit so the server recognizes you.
Redis An extremely fast database stored in computer memory (RAM) rather than on disk. Used to store sessions and cache data. It's like having answers written on a whiteboard (fast to read) vs. searching through a filing cabinet (slower disk database).
Middleware Code that runs automatically on every request, before the controller. Like a security guard at a building entrance. The SecurityHeadersMiddleware is one guard; the authentication check is another. Every page load passes through them.
Route A mapping between a URL and a function that handles it. E.g., "when the URL is /auth/microsoft, run MicrosoftOAuthController::redirectToMicrosoft()." The app has hundreds of routes for different pages and API calls.
Blade Laravel's templating language for HTML files. It adds features like {{ variable }} to print values, @if/@endif for conditions, and {{ route('name') }} to generate URLs. Files end in .blade.php.
CSRF Token A secret code hidden in every HTML form. When the form is submitted, the server checks the code matches. This prevents attackers from tricking you into submitting a form on another website (Cross-Site Request Forgery attack).
Session Fixation An attack where an attacker gets you to visit a link with a pre-set session ID in it, then waits for you to log in. Once you log in with that ID, the attacker (who knows the ID) now shares your authenticated session. Regenerating the session ID after login blocks this entirely.
Tenant ID Every Microsoft organization (company) has a unique Tenant ID in Azure. It identifies which organization's users are allowed to authenticate. Ours is the Tanseeq Investment Azure tenant.
Azure AD / Microsoft Entra Microsoft's identity service. It's the system that manages all company users, their passwords, and their access rights. When a user logs in to our app via Microsoft, Azure AD is the system doing the actual authentication.

10. Environment Variables That Control Login

These values are stored in the .env file on the server. They are never committed to Git or shared. All sensitive values (secrets, passwords) must be kept private.

Variable Example Value Purpose Where to get it
AZURE_TENANT_ID a8255ea0-aa54-... Identifies our company's Azure directory Azure Portal → Azure Active Directory → Overview
AZURE_CLIENT_ID 401538ec-9257-... Identifies our registered application in Azure Azure Portal → App Registrations → your app → Application (client) ID
AZURE_CLIENT_SECRET D5w8Q~XQ... Password our server uses to prove to Microsoft it is our app Azure Portal → App Registrations → your app → Certificates & secrets
MICROSOFT_REDIRECT_URI ${APP_URL}/auth/microsoft/callback URL Microsoft sends the user back to after sign-in. Must exactly match what is registered in Azure Portal. Must be set manually; must match Azure Portal registration
MICROSOFT_ALLOWED_DOMAIN tanseeqinvestment.com Only emails ending in this domain can log in. Leave blank to allow any Microsoft account. Set by the developer/IT administrator
SESSION_ENCRYPT true Encrypts all session data before saving to Redis Set by the developer
SESSION_DRIVER redis Tells Laravel to store sessions in Redis instead of files Set by the developer
REDIS_HOST golden-dingo-128859.upstash.io Address of the Redis server that stores sessions Upstash dashboard → your database → Endpoint
APP_KEY base64:xOTvFP... The encryption key for sessions, cookies, and all encrypted data. Must never be changed in production (all sessions would become invalid). Generated by php artisan key:generate
🔴 Critical: Never share or commit these values The .env file must never be committed to Git, shared by email, or stored in a screenshot. If AZURE_CLIENT_SECRET is exposed, an attacker could impersonate our app to Microsoft. Rotate the secret immediately in Azure Portal if it is ever exposed.
